## Build and launch

```bash
xcodegen generate --spec App/project.yml
xcodebuild -project App/Lift.xcodeproj -scheme Lift -configuration Debug -derivedDataPath build/xcode \
  -packageAuthorizationProvider netrc -skipPackagePluginValidation build
open build/xcode/Build/Products/Debug/Lift.app
App/smoke-test.sh build/xcode/Build/Products/Debug/Lift.app   # launch check, writes only to a temp folder
```
Local SwiftPM: `swift build`/`swift test --disable-keychain`. Without `--disable-keychain` (or `xcodebuild -packageAuthorizationProvider netrc`), SwiftPM's download of the GLTFKit2 binary hangs in a Keychain lookup that can't prompt.

## Decisions to fold into the spec

- **Project:** XcodeGen (`App/project.yml`) generates the one Xcode project. A real bundle is needed for notifications, the login item, embedding GLTFKit2 and copying `lift-mcp`. The `.xcodeproj`, Info.plist and entitlements are generated and git-ignored. The build is ad-hoc signed, with no sandbox and no hardened runtime.
- **No XCUITest:** UI testing needs a one-time interactive automation approval. Instead, `-LiftSmokeTest YES` makes the app print the sidebar titles and quit. The smoke test passes `-workdir`/`-setupDone` on the command line and sets `CFFIXED_USER_HOME`, so it never writes the user's preferences.
- **Wizard order:** working folder (plus export folder and cleanup) → helper tools (with the password dialog explained first; Metal only when needed) → models → Hugging Face walkthrough (optional) → AI-assistant snippet. The folder step comes first because opening the folder starts the engine. The step reached is saved, so a quit setup resumes there.
- **Outside the workdir:** the workdir path, `setupDone`, `setupStep` and `aboutShown.<id>` live in UserDefaults, through `PreferenceStore`. Tests use memory.
- **App settings are LiftCore settings,** so HTTP and MCP can change them. The app reconciles `launch_at_login` with `SMAppService`; if the system refuses, it shows an alert and writes the actual state back, with no retry loop.
- **Moving the working directory** is UI-only (LiftCore can't reopen itself), behind a confirmation.
- **`lift_worker`** is copied to `<workdir>/runtime/` at each launch, so bytecode caches never write into the signed bundle.
- **Developer mode** (`dev_recipes`) is the opt-in developer view: Test Cube, raw options, install commands, commits, Change Pin and the Mac shim.
- **README:** MarkdownUI (`gonzalezreal/swift-markdown-ui` 2.4.1, GitHub theme), with relative links and images resolved at the pinned commit. Links open in the browser.
- **Viewers are chosen by file extension:** glTF through GLTFKit2, OBJ and USDZ through SceneKit, with Textured, Clay, Wireframe and Skeleton modes. FBX has no preview, only Reveal in Finder.
- **Principle 2:** no model is preselected, files aren't routed by type, there are no warmth hints, and the queue order is LiftCore's. The mockup's "Warm model first", "Retry with Low memory mode" and "Your default" are dropped.
- **No recipe sources or URL entry anywhere** (spec §4). Unsupported or invalid recipes are listed with a plain reason.
